Step 0 · Do this once

Setup

  1. Install the Copilot CLI. npm i -g @github/copilot (1.0.103). The course's Python SDK calls the model through the copilot command, so installing the App alone is not enough. The CLI shares its sign-in with App 1.1.32; no second login is needed.
  2. Create the Python environment. python3.12 -m venv ~/.venvs/hol_ghc_app, install requirements.txt from public PyPI, then run playwright install chromium. The course commands use Microsoft's packagefeedproxy mirror, which is reachable from the public internet (tested 2026-10-30: npm and PyPI both return 200). Using the public registries here was a personal choice; the original commands work too. The venv lives outside OneDrive so it is not synced.
  3. Confirm the model. Continue only if python tools/probe.py lists gpt-6-luna. If it does not, fix account access first instead of switching models.
  4. Pick the project and workspace in the App. The App's hol_ghc_app project points to ~/Projects/hol_ghc_app. When starting a session, change Workspace from New worktree to Current checkout; this is what the course calls a local-folder session.
  5. Pick the mode and model. Below the input box choose Autopilot, and pick GPT-6 Luna under More models. Do not leave it on Auto.
  6. Set tool permissions to Approve all. Autopilot → Tool permissions → Approve all. Otherwise nobody is there to approve commands in Autopilot and every command is denied (see Lab 1, first attempt).

Lab 02 · 45 min

Product story: a vertical Surface Laptop Ultra video Passed

Learn the Plan → review → Autopilot way of working. First get only a plan, approve it after reading it, then let it run. The official product page is the only source of facts, and what gets checked is the real MP4 file, not a web preview.

Steps in the App

  1. Start a session in Plan mode and send the README's "plan first, do not execute" prompt. The App read the existing project, checked the facts on Microsoft's product page, and wrote a 116-line plan.md: 6 shots, a source check table, an asset list, draft narration, CLI steps and acceptance criteria.
  2. While planning, the App stopped to ask: use a fixed, reviewed narration, or keep SDK generation with stricter checks? We chose the latter. The course's acceptance relies on the plan and autopilot model traces in story.json; a fixed script would leave no such record.
  3. In the Review plan panel choose "Exit plan mode", switch the mode to Autopilot, and send the README's approval prompt. The App runs fetch_sources → story.py → video.py prepare / voice → hyperframes check / render → ffprobe, and decodes six frames from the final video to check them.

Lessons

Lessons and trade-offs

MOST IMPORTANT

Autopilot needs Approve all

Tool permissions default to Always ask. In Autopilot nobody approves, so every command is denied and the agent can only read code.

Trade-off: Approve all lets the agent run commands in this repository without confirmation. That is what the course's continuous execution depends on; the prompts set the limits ("only change LabN/Code, do not commit").

REPOSITORY TRUST

We chose Skip for now

The repository has no hooks, MCP or extension config, so it does not need to be trusted; trusting it would let such config run code automatically in the future.

Note: without trust the App shows "Tool permissions limited", but commands still run under Approve all.

SCREEN LOCK

The App keeps working; the UI needs an unlocked screen

The Mac locked as soon as the remote desktop disconnected, and the App window could not be reached. The fix: while unlocked, send Labs 2/3/4 in one go (they change different folders, so they can run in parallel), and add "do not stop to ask questions" to the prompts.

Cost: fewer progress screenshots, only "when sent" and "when done".

WORKSPACE

Current checkout switches back to main

The run branch created beforehand was switched back to main by the App; the changes stayed uncommitted in main's working tree.

To keep them, create a branch with git switch -c first, then commit.

PACKAGE SOURCES

Both the mirror and public registries work

The README uses packagefeedproxy.microsoft.io. This run used the public PyPI and npm registries with pinned versions, with the same results.

Correction: the first version of this manual said the mirror was unreachable for outside accounts, without testing it. On 2026-10-30 it was reachable from the public internet, and the upstream Pages workflow uses it.

SIDE EFFECT

The App rewrote Lab2/README.md

The agent changed the README commands to the local venv path and public registries. Fine for reproducing locally, but it should not go back into the course repository; revert that file before committing.

SYSTEM PROMPT

Python asks for local network access

macOS asks this when the local server starts. The labs only use 127.0.0.1, so choosing "Don't Allow" has no effect on them.

PLAN QUESTIONS

Plan mode stops to ask about key choices

While planning Lab 2, the App asked whether the narration should be a fixed script or generated through the SDK. That is the point of Plan: decisions that shape the implementation are made by a person.
