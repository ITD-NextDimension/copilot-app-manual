This chapter combines setup with an App tour: each time you install something, you also see which App control it relates to. It takes about 25 minutes; please do it before class. After that, the four labs need only the App and one terminal window.

App feature

Model menu what each line does

python tools/probe.py grep gpt-6-luna verification/capabilities.jsonpython tools\probe.py Select-String gpt-6-luna verification\capabilities.json

WhyThis proves a Python program can reach the model through the Copilot SDK. The App working doesn't prove the SDK works, and the lab scripts go through the SDK.

Checkgpt-6-luna is in the model list and the second command finds it; there is no sign-in error.
CLI feature

Copilot CLI and the Python SDK how they connect

  • The Python github-copilot-sdk doesn't talk to the cloud itself: it starts the copilot command in the background and talks to it over standard input/output (stdio). That's why the CLI must be installed and signed in.
  • The App and the CLI share the ~/.copilot folder (%USERPROFILE%\.copilot on Windows): session records in session-state/, plus plugins, Skills and extensions. A plugin installed with the CLI shows up in the App without a restart (Lab 2 uses this).
  • The course's tools/agent.py gives each session a single "task complete" tool: no browsing, no file access, no sub-agents, and no silent model switch when the model is unavailable.

0.7 Set the mode, permissions and workspace

In New session, check each button under the prompt box.

Mode

Click the mode button (it reads Interactive by default) to see the three modes. The prompt box border changes colour: grey for Interactive, blue for Plan, green for Autopilot.

Mode menu: Interactive (Step-by-step collaboration), Plan (Plan first, execute when ready), Autopilot (End-to-end execution without interruption), plus Tool permissions. With Plan the border turns blue and the placeholder reads "Plan a task…". With Autopilot the border turns green and the placeholder reads "Delegate a task…".

Tool permissions

In the same menu open Tool permissions and choose Approve all.

WhyAutopilot doesn't stop to wait for you. With Always ask, nobody approves its commands, so every command is refused and the run only reads files.

Tool permissions: Always ask, Assisted, Approve all.
SafetyApprove all lets the agent run commands without asking. Use it only on the course folder and practice data.

Folder, Run on, Where to work

Folder: make sure gh_app_workshop is ticked. Run on: keep This computer. Cloud runs remotely, but the course needs your local Python, FFmpeg and browser. Where to work: the default is New worktree; change it to Current checkout. After the change: gh_app_workshop · This computer · Current checkout.

WhyNew worktree copies the folder for each session. The course changes, runs and checks the one copy you cloned, so use Current checkout.

App feature

Three modes and "mode memory" modes

  • Interactive: stops after each step; good when the direction isn't settled.
  • Plan: researches and writes a plan (plan.md); changes nothing until you approve. For vague, wide or costly-to-undo tasks (Lab 2).
  • Autopilot: runs to the end when the task is well bounded (Labs 1, 3 and 4).
  • A new session keeps the previous session's mode. In this run Lab 1 used Autopilot, so the Lab 2 session opened in Autopilot; Lab 2 used Plan, so the Lab 3 session opened in Plan. Check the border colour before every send.
  • Where to work and Run on are remembered too. Under Current checkout all sessions share one working folder, so the Changes panel shows the whole folder's changes, not just this session's (you'll see this in Lab 3).

Story: The studio has a team event next week. You want a Chinese chess game that runs in the browser, without learning to code first. Your request isn't "write me some code" but "let my colleagues play, and prove the rules aren't made up".

Logical and code architecture

Logical architecture: you write only the request and the acceptance criteria. The App session (Autopilot) reads the code, edits the page, adds tests, then clicks through it with Playwright. All rule decisions are made in Python; the page only draws and handles clicks.

Code architecture: generate.py calls GPT-6 Luna through tools/agent.py to produce the page shell generated.html. app.py uses tools/web.py to serve the page on local port 8011 with /api/state, /api/select, /api/move, /api/undo and /api/reset. Every legal move is computed by xiangqi.Game.

App feature

Repository trust vs tool permissions two separate gates

  • Repository trust decides whether this repository's configuration and extensions may run. It's remembered per repository.
  • Tool permissions (0.7) decide whether the agent asks you each time it uses a tool.

Logical and code architecture

Logical architecture: a Plan session produces only a plan (plan.md). After you approve, the session switches to Autopilot and executes: the agent writes the scenes following the HyperFrames Skills, synthesises the voice-over with edge-tts, and renders the MP4 with the HyperFrames CLI.

Appendix

A · Stop the background servers after class

The labs leave several local servers running: 8011 (Lab 1), 8013 (Lab 3), 8014 (Lab 4) and 3002 (Lab 2's HyperFrames Studio). The easiest way is to click Background at the bottom of each session and stop them one by one. You can also stop them by port in a terminal:

lsof -nP -iTCP:8011 -sTCP:LISTEN kill <PID shown above>Get-NetTCPConnection -LocalPort 8011 -State Listen | Select-Object OwningProcess Stop-Process -Id <OwningProcess shown above>

Repeat with 8013, 8014 and 3002. Stop only servers you started; leave processes you don't recognise alone.

B · Reset between classes (instructors)

The agent changes course files and generated results. Before the next class, restore the four labs to the repository version from the course root:

git status --short git restore --source=HEAD -- Lab1 Lab2 Lab3 Lab4 git clean -fd -- Lab1 Lab2 Lab3 Lab4

git clean deletes new untracked files in the lab folders (for example Lab 2's REVIEW.md and Lab 3's observatory.png) but leaves ignored folders such as .venv and node_modules. Read git status before running it.
