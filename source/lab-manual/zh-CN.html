CLI 功能

Copilot CLI 与 Python SDK CLI & SDK

  • Python 的 github-copilot-sdk 不直接连云端：它在后台启动 copilot 命令，通过标准输入输出（stdio）和它对话。所以 CLI 必须装好、登录好。

0.7 设置模式、权限和工作位置

在 New session 里依次检查输入框下方的按钮。

模式（Mode）

点模式按钮（默认显示 Interactive），弹出三种模式。输入框的边框颜色会跟着变：Interactive 灰色、Plan 蓝色、Autopilot 绿色。

Mode 菜单：Interactive（Step-by-step collaboration）、Plan（Plan first, execute when ready）、Autopilot（End-to-end execution without interruption），以及 Tool permissions。 选 Plan 后边框变蓝，提示文字变成 “Plan a task…”。 选 Autopilot 后边框变绿，提示文字变成 “Delegate a task…”。

工具权限（Tool permissions）

在同一菜单打开 Tool permissions，选 Approve all。

为什么Autopilot 中途不会停下来等人。如果权限是 Always ask，它每次运行命令都没人批准，命令会全部被拒绝，结果只读了文件、什么也没做成。

Tool permissions：Always ask、Assisted、Approve all。
安全Approve all 允许 Agent 不经确认运行命令。只在课程文件夹和练习数据上使用。

文件夹、Run on、Where to work

文件夹：确认勾选的是 gh_app_workshop。 Run on：保持 This computer。Cloud 会在云端运行，而课程需要你电脑上的 Python、FFmpeg 和浏览器。 Where to work：默认是 New worktree，要改成 Current checkout。 改好后：gh_app_workshop · This computer · Current checkout。

为什么New worktree 会为每个会话复制一份独立目录；课程要在你克隆的这一份上直接修改、运行和验收，所以用 Current checkout。

App 功能

三种模式与“模式记忆” modes

  • Interactive：一步一停，适合方向未定时边做边看。
  • Plan：先调研、写计划（plan.md），你批准之前不改任何文件。适合需求模糊、牵涉面广、改错代价高的任务（Lab 2）。
  • Autopilot：边界清楚时连续执行到底（Lab 1、3、4）。
  • 新会话会沿用上一个会话的模式。实跑中 Lab 1 用了 Autopilot，Lab 2 新会话默认就是 Autopilot；Lab 2 用了 Plan，Lab 3 新会话默认就是 Plan。每次发送前看一眼边框颜色。
  • Where to work 和 Run on 会被记住；Current checkout 下所有会话共用同一份工作目录，所以 Changes 面板显示的是整个文件夹的改动，不只是当前会话的（Lab 3 会看到）。

Lab 1 · 楚河汉界：把需求说清楚

故事：工作室下周有团队活动，你想做一个能在浏览器里玩的中国象棋，又不想先学编程。你的需求不是“帮我写代码”，而是“让同事玩起来，并且能证明规则没有乱来”。

学会什么把需求写成“目标 + 约束 + 验证 + 停止条件”；读 Agent 的报告和 diff；在 App 里验收作品
模式Autopilot · GPT-6 Luna · Medium
实跑耗时Agent 运行约 10 分钟，加验收约 5 分钟

逻辑架构与代码架构

逻辑架构：你只写需求和验收标准；App 会话（Autopilot）去读代码、改页面、补测试，再用 Playwright 真点一遍。规则判断全部在 Python 里，页面只负责显示和点击。

App 功能

会话界面 session view

lsof -nP -iTCP:8011 -sTCP:LISTEN kill <上一条显示的 PID>Get-NetTCPConnection -LocalPort 8011 -State Listen | Select-Object OwningProcess Stop-Process -Id <上一条显示的 OwningProcess>
